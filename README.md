# 서울 교통 대시보드

삼성 스마트모니터 M7 세로 화면용 정적 대시보드입니다. GitHub Pages 화면이 Google Apps Script를 통해 서울시 지하철 및 서울특별시 버스도착정보를 조회합니다. 직접 HTTP API를 호출하던 방식은 연결 문제로 제거했습니다.

**코드 편집 없이 설치하려면 `npm run setup:relay`를 실행하세요.** [자동 설치 안내](apps-script/README.md)를 참고하세요. Google 계정에서 새 웹 앱을 배포한 뒤, 대시보드에 `/exec` URL과 접속 코드를 입력합니다. 별도 PC 서버는 필요하지 않습니다.

## 사용

GitHub Pages 등에서 저장소 루트의 정적 파일을 제공하고 `index.html`을 엽니다. 필요한 파일은 `index.html`, `script.js`, `browser-api.js`, `route-catalog.js`입니다. 저장소 웹 화면은 대시보드가 아닙니다. 로컬 개발은 Node.js 22 이상에서 `npm start` 후 `http://127.0.0.1:3000`으로 확인합니다. `server.js`는 정적 미리보기 전용이며 `/api` 프록시는 제거했습니다. `.env`를 사용하지 않습니다.

API 키 두 개는 Apps Script의 스크립트 속성에 저장합니다. 대시보드 설정에는 중계 URL과 접속 코드만 저장합니다. 기존 장소 설정은 유지하며, 다시 저장하면 브라우저의 예전 API 키 필드는 제거됩니다.

여러 조건은 쉼표로 구분합니다.

- 지하철: `노들/9/공항방향`. 역명/호선/API 상하행 코드도 지원합니다. 공항방향은 다음 역 방면이 **노량진**인 열차를 고릅니다. 상행·하행으로 임의 변환하지 않습니다. 응답에서 방면을 판별할 수 없으면 오류를 표시합니다. 필터 후 최대 2대 표시합니다.
- 버스: `20726/동작08, 20014/360`. 정류소 ARS 번호/노선명 형식으로 입력합니다. 노선명은 공식 파일의 ID 사전에서 변환합니다. 사전에 없으면 오류이며, 검증한 9자리 노선 ID를 직접 입력할 수도 있습니다.
- **내 조회조건 채우기**는 위 조건만 입력하고 중계 설정은 유지합니다. 저장 전까지 적용되지 않습니다.

## 검증한 정적 정보와 미확인 항목

서울시 공식 `서울시버스노선ID정보(20260902).xlsx`에서 동작08=`119900009`, 360=`100100057`을 확인했습니다. `서울시버스노선별정류소정보(20260902).xlsx`에서 20014·360은 노들역, 내부 정류소ID `119000014`, 순번 35입니다.

사용자가 정류소 번호 착오를 확인했으므로 기본값을 **20726/동작08(신동아정문)**으로 수정했습니다. 기존 저장 설정은 덮어쓰지 않습니다. 정적 자료는 노선 개편에 따라 달라질 수 있습니다.

## API 구조

| 종류 | 서비스 | 선택 방법 |
| --- | --- | --- |
| 지하철 | `realtimeStationArrival/0/100/{역명}` | 응답의 역명·호선·다음역 방면 또는 명시된 방향으로 필터 |
| 버스 | `arrive/getArrInfoByRouteAll?busRouteId=…&resultType=json` | 응답의 busRouteId와 5자리 arsId가 모두 일치해야 표시 |

버스의 `stationinfo/getStationByUid` 및 routeinfo 서비스는 사용하지 않습니다. 노선 전체 응답은 같은 갱신 주기 내에 공유하므로 같은 노선 여러 정류소 조회 시 API 요청을 합칩니다. 중계 주소가 비어 있으면 실제 요청 없이 설정 안내를 표시합니다.

버스 오류 4(노선 없음), 6(실시간정보 실패), 8(운행 종료)을 구분하며 오류를 정상 빈 결과로 숨기지 않습니다. 연결·JSON·방향 해석 실패도 표시합니다. 실패 시 이전 도착정보를 지웁니다. 화면 갱신 시각과 API 생성 시각을 구분하고, 제공기관이 생성 시각을 주지 않으면 미제공으로 표시합니다. 지하철의 시간형 안내는 한국 시각 recptnDt를 기준으로 barvlDt(양수), 없으면 원본 메시지의 분·초에서 경과시간을 빼 매초 추정 시간을 표시합니다. 상태형 안내는 그대로 유지합니다. 시각을 읽지 못하면 원본임을 표시하며, 예정 시각이 지나도 실제 도착으로 단정하지 않습니다. 이미 출발한 열차(arvlCd=2)는 제외합니다. 버스 표시는 변경하지 않습니다.

기본 갱신 주기는 30초이며, 설정에서 최소 30초까지 선택할 수 있습니다. 180초는 API의 필수 제한이 아니라 기본 호출량을 고려한 값입니다. 버스 두 노선을 24시간 조회하면 주기 요청만 약 960회이며, 수동 갱신·재접속·여러 기기 사용은 추가 호출입니다. 실제 승인 한도와 사용 패턴에 맞춰 간격을 늘리세요. 요청은 최대 3개 동시, 브라우저 응답 대기는 최대 35초입니다. 숨겨진 화면은 다음 주기 조회를 중단합니다.

## 연결 제한과 검증 범위

HTTP 샘플 요청에서는 지하철 정상 JSON과 버스 인증 오류 JSON 및 CORS 허용 헤더가 확인됐고 HTTPS는 프록시 타임아웃이 발생했습니다. GitHub Pages의 HTTPS 페이지에서 HTTP API로 직접 요청할 수 없으므로 중계를 사용합니다.

Apps Script의 공식 JSONP 방식을 사용해 CORS 헤더에 의존하지 않고 공개 교통정보를 받습니다. 중계 배포 권한·실제 키·M7 성공 응답은 사용자 배포 후 검증해야 합니다. 모의 테스트는 실제 연동 성공을 의미하지 않습니다. 모니터의 물리적 회전과 세로 뷰포트도 별도 확인이 필요합니다.

## 정적 ID 사전 갱신

출처: [서울시 버스노선 기본정보 항목정보](https://data.seoul.go.kr/dataList/OA-15262/F/1/datasetView.do), [서울시 버스 노선 정보 조회](https://data.seoul.go.kr/dataList/OA-1095/L/1/datasetView.do). 공공누리 제1유형, 출처 서울특별시.

원본 노선 ID XLSX를 받은 뒤 `python3 scripts/build-route-catalog.py 원본.xlsx > route-catalog.js`로 재생성합니다. 원본 날짜 주석도 갱신하세요. XLSX에는 비밀키가 없으며 앱 실행 때 다운로드하지 않습니다. 확인 절차와 서비스 명세는 [검토 문서](docs/transit-api-review.md)를 참고하세요.

검증: `npm test`. 별도 패키지 설치가 필요하지 않습니다.

수동 갱신은 중계에 `refresh=1`을 보내 API를 다시 요청합니다. 이 기능은 최신 Apps Script 코드로 교체하고 기존 배포를 새 버전으로 갱신해야 작동합니다. 구버전이면 화면에 캐시 우회 미지원 안내가 나옵니다. 자동 요청 캐시는 20초입니다. 새 요청이 원천 생성 시각의 변경을 보장하지는 않습니다.

사용자 웹 앱 주소를 기본값으로 지정했습니다. 새 기기는 중계 주소 입력 없이 접속 코드만 입력하면 됩니다. 빈 주소를 저장한 기존 기기도 기본값을 사용하며, 기존에 따로 저장한 주소는 유지됩니다. 설정의 ‘중계 주소 · 기본 설정됨’을 펼치면 변경할 수 있습니다.

## 모니터에 예전 화면이 보일 때

Apps Script 재배포는 중계만 업데이트합니다. 대시보드는 GitHub Pages 배포 후 브라우저가 새 HTML과 JS를 받아야 합니다. 화면 하단 버전으로 확인하세요. JS 파일 주소에도 같은 버전을 붙여 파일 변경 후 캐시가 재사용되지 않도록 했습니다. 앞으로 프런트 파일이 바뀌면 HTML의 세 파일 주소와 표시 버전을 함께 올립니다.

최초 캐시 갱신은 `https://kisupahn.github.io/dashboard/?v=20261103.1`로 접속합니다. 쿼리만 달라지므로 저장한 접속 코드와 장소 설정은 유지됩니다. 그래도 이전 화면이면 브라우저를 완전히 종료하고 다시 여세요. 데이터 삭제는 저장한 설정도 지우므로 마지막 수단입니다.

## 간결한 모니터 화면

버스 설정 순서대로 먼저 표시하고 지하철을 뒤에 표시합니다. 제목은 정류소·역명만 사용하며, 조회 시각·원천 설명·계산 과정은 기본 화면에서 제거했습니다. 진단은 설정 안에서 확인할 수 있습니다. 정류소·역별 카드 아래에 노선별 행을 표시합니다. 각 행은 노선명과 두 대의 도착정보로 구성하며 없는 정보는 공란입니다. 지하철은 호선·행선지별로 묶습니다. 실제 연결 오류는 숨기지 않습니다.

카드 헤더는 교통수단 아이콘·정류소/역명·노선번호 배지로 구성합니다. 버스는 초록, 지하철은 9호선 골드 계열입니다. 조회 중에는 (로딩중), 성공 후 없는 도착편은 공란입니다. 한글 서체는 Noto Sans KR을 요청하며 외부 폰트가 지연되거나 실패하면 기기의 한글 서체로 표시합니다.

## 터치 갱신과 노선별 행

설정 버튼과 설정 패널을 제외한 일반 화면을 누르면 원천 재조회를 요청합니다. 조회 중 중복 터치는 무시하며, 설정 조작이나 링크·입력 필드 클릭은 조회를 유발하지 않습니다. 기존 갱신 버튼은 키보드·리모컨 조작용으로 유지합니다.

버스는 같은 ARS 번호의 설정들을 한 카드에 합치고, 각 노선을 `노선명 | 가장 가까운 차 | 다음 차` 행으로 표시합니다. 같은 이름의 반대편 정류소는 ARS가 다르므로 합치지 않습니다. 지하철은 같은 역 아래에 `호선 / 행선지 | 가장 가까운 열차 | 다음 열차`로 묶습니다. 같은 열차번호가 중복된 응답은 해당 행에서 중복 제거합니다.

## 화면 20261103.9 — 정류장별 설정

기존 키·중계 주소·조회 조건을 유지하면서 정류장 항목으로 자동 변환합니다. 각 항목은 버스/지하철 선택, 장소, 노선 및 방향으로 구성하며 추가·삭제·위아래 이동 후 저장합니다. 예: 버스 / 20726 / 동작08, 버스 / 20014 / 360, 지하철 / 노들 / 9호선 공항방향. 버스 이름 입력은 현재 등록한 신동아정문·노들역을 지원하며 다른 곳은 5자리 코드를 입력하세요. 같은 정류소는 첫 등장 위치의 카드에 합쳐집니다.

자동 조회 중 기존 값을 유지하고 작은 로딩 표시만 보여줍니다. 같은 내용이면 카드 내부 DOM도 재생성하지 않습니다. 오류 시 기존 값 옆에 오류를 표시하고, 운행 종료가 확인되면 비웁니다. 진단에서 실제 중계 요청 왕복시간(ms)을 확인할 수 있습니다. Google 중계나 원천 API의 응답시간 자체가 단축됐다는 의미는 아닙니다.

자동 조회 30회 후 카드를 숨기고 새로고침 버튼을 표시하며, 자동 조회를 멈춥니다. 화면을 누르면 수동 원천 재조회를 하고 카운트를 초기화합니다. 최초·수동 조회는 자동 횟수에 포함하지 않습니다. 날짜·요일과 전체화면 전환을 추가했습니다. 전체화면이 지원되지 않는 브라우저에는 안내를 표시합니다. 오래된 정보 상태점과 도착 임박 굵기 변경은 추가하지 않았습니다.

노션 연동은 아직 하지 않았습니다. 추후 설정 저장소로 사용한다면 교통수단·장소·노선/방향·순서·활성화 필드를 권장하며, 접속 시 및 설정 변경 시에만 동기화하고 도착정보의 30초 조회 경로와 분리하는 구성이 적합합니다.

## 화면 20261103.10 — 글자 크기

## 화면 20261103.12 — 접속 코드 수정 · 뉴스 플레이어

중계 접속 코드 입력칸은 평소 비활성화된 빈칸에 고정 문구(저장됨/미설정)만 표시합니다. 저장된 코드와 길이를 DOM 입력값으로 채우지 않습니다. “수정하기”(처음에는 “입력하기”)를 누르면 빈칸을 활성화하고 새 코드를 입력합니다. 취소하거나 저장하지 않고 설정을 닫으면 기존 코드를 유지합니다. 수정 중 빈 코드를 저장할 수 없으며, 다른 설정만 저장할 때는 기존 코드를 유지합니다. 코드 자체는 기존과 같이 브라우저 localStorage에 보관합니다.

교통정보 아래에 뉴스 플레이어를 추가했습니다. 기본은 [YTN 공식 라이브 페이지](https://www.ytn.co.kr/_hd/hd_live.html)에 연결된 국내 시청용 유튜브 주소입니다(2026-11-03 확인). 설정의 “뉴스 영상 · 라이브 주소”에서 유튜브 공유 주소(watch, youtu.be, live, embed, shorts)를 수정하고 저장하거나 “뉴스 재생”을 꺼서 플레이어를 제거할 수 있습니다. 방송이 종료되거나 주소가 바뀌면 새 라이브 공유 주소로 바꿔야 합니다. 채널 홈이나 채널의 /live 주소는 영상 공유 주소가 아니므로 지원하지 않습니다.

## 화면 20261103.13 — 가로 설정 · 뉴스 확대 · 가로 화면

정류장 편집은 `[버스/지하철 버튼] [정류장명·코드] [노선·방향]` 한 줄로 표시합니다. 같은 교통수단 버튼을 누를 때마다 버스와 지하철로 전환하며, 종류 변경 시 이전 입력은 비웁니다. 뉴스 재생 체크와 영상 주소도 한 줄로 배치했습니다.

뉴스 시작 시 음소거를 해제(`mute=0`)하고 자동 재생을 요청합니다. 유튜브 기본 재생·음량 버튼을 사용할 수 있습니다. 소리가 있는 자동 재생의 실제 허용 여부는 삼성 모니터 브라우저의 정책에 달려 있으며, 차단되면 플레이어에서 직접 재생해야 합니다. 코드가 브라우저 정책을 강제로 해제하지는 않습니다. 위 버전의 무음 시작 설정을 대체합니다.
